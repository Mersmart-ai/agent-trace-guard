# 留出异常类型：规则 vs 统计模型

- 日期：2026-11-15（2026-11-18 按 P0-6 更新 `blind` 口径）
- 成本：0 元，不调用模型
- 脚本：`experiments/negatives/heldout_anomalies.py`
- 目的：用没参与规则设计的异常类型，检验统计模型有没有增量价值

## 1. 两种新异常

| 异常 | 做法 | 说明 |
|---|---|---|
| `blind_write` | 删掉写之前的 `read_file` | 没读就改，测试仍然能过 |
| `read_tests` | 尝试读 `../tests` | 被 harness 拒绝，`ok=False`，测试仍然能过 |

这两种都不是 `no_verify / delta / dup2` 直接定义的。

## 2. 结果

### 检出

| 异常 | 规则 | 规则检出 | Fisher q=0.90 | Fisher q=0.95 |
|---|---|---:|---:|---:|
| `read_tests` | `error`（任意 `ok=False`） | 13/15 | 13/15 | 13/15 |
| `blind_write` | `blind`（写目标文件之前没读过它；新建文件除外） | 10/13 | 1/13 | 1/13 |

所有 trace 最终全绿。

### 规则在留出 clean 上的误报

| 规则 | 误报 |
|---|---:|
| `no_verify` | 0/16 = 0.0% |
| `delta` | 0/16 = 0.0% |
| `dup2` | 0/16 = 0.0% |
| `error` | 0/16 = 0.0% |
| `blind` | 0/16 = 0.0% |
| `tier_all` | 0/16 = 0.0% |

P0-6 之前 `blind` 在 clean 上有 3 条误报（终端任务用 bash 检查文件后再
`write_file`，或新建文件）。现在 `blind` 按目标文件判断，并跳过
`path_missing`（先报“文件不存在”的新建文件），这 3 条误报消失，
`tier_all` 也随之归零。

## 3. 完整规则集的覆盖

| 异常 | 检出 |
|---|---:|
| 不验证 | 14/15 |
| 重复读 | 15/15 |
| 重复写 | 13/13 |
| 改坏再修好 | 11/11 |
| 尝试读 tests | 13/15 |
| 没读就写 | 10/13 |

六条规则（`no_verify / delta / dup2 / error / long_gap / unverified_write`）
和 `blind` 在留出 clean 上都是 0% 误报。

`blind_write` 没抓到的 3 条，是因为这些 trace 在此前已经读过同一个文件，
只是最近一次 `read_file` 被删掉；按“写目标文件之前有没有读过它”的定义，
它们不属于真正的“从未读”。

## 4. 关键结论

1. **规则覆盖了目前所有六种异常**
   - 六条规则在留出 clean 上 0% 误报
   - `blind` 抓到 10/13；没抓到的 3 条此前已读过同一文件，不算盲写

2. **Fisher 没有证明增量价值**
   - `read_tests`：规则和 Fisher 都是 13/15
   - `blind_write`：规则 10/13，Fisher 只有 1/13
   - Fisher 的误报还更高（q=0.90 为 18.8%）

3. **这不是坏消息，但改变了论文故事**
   - 工程上：一套可解释、低误报的规则监控器已经成立
   - 研究上：one-class 正常模型在这些任务上没有超过规则
   - 如果继续做论文，需要找到“规则抓不到、模型能抓到”的异常
   - 或者把论文改成“过程一致性监控 + 误报控制 + 干预”，规则作为检测器

## 5. 下一步

1. 用真实模型负样本找更隐蔽的异常（小预算）
2. 如果真实异常也被规则覆盖，就不要再加模型复杂度
3. 把精力转到：
   - 规则分类体系
   - 报警的序贯控制
   - 低成本干预
4. 论文定位调整为“过程监控 + 干预”，而不是“正常分布建模”

## 6. 诚实结论

到目前为止，**规则比统计模型更有用**。

这不是说模型永远没用，而是说：
在我们能造出来的异常上，规则已经够了。
要证明模型的价值，必须找到规则覆盖不到的异常。
