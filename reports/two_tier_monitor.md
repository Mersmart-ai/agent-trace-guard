# 两层监控：规则 + 统计模型

- 日期：2026-11-15
- 成本：0 元，不调用模型
- 脚本：`experiments/cv_calibration.py`
- 测试集：`experiments/splits/task_split_v1.json`（15 个留出任务）

## 1. 为什么要试规则

Fisher 在 q=0.90 时误报 16.2%，q=0.95 时误报 2.5% 但检出掉得厉害。
有些偏离其实可以用确定性规则直接抓，不需要统计模型。

试了三条规则：

| 规则 | 含义 |
|---|---|
| `no_verify` | 整条 trace 一次 `run_tests` 都没调 |
| `delta` | 任意一步出现新的红测试（集合差；修好 a、弄坏 b 也算） |
| `dup2` | 任意一步 `repeat_streak >= 2`（连续重复至少 3 次） |

## 3. 怎么解读

### 好的一面

两层规则在留出任务上做到：

- **0% 误报**
- 14/15、15/15、13/13、11/11 检出
- 所有脚本 trace 最终全绿

这是一个很强的工程结果：已知的过程违规用规则抓，几乎不误报。

### 但要非常小心

1. **规则就是偏离的定义**
   - `no_verify` 专门抓“不验证”
   - `delta` 专门抓“弄红”
   - `dup2` 专门抓“重复”
   用同一套定义生成负样本，再用同一套定义检测，当然好看。

2. **`delta` 的 0 误报是标签决定的**
   `clean_success` 的定义里就排除了 regression，所以 `delta` 在 clean 上必然 0 误报。
   这不是模型的功劳。

3. **`no_verify` 漏了一条**
   `term_0010` 有多次 `run_tests`，只删最后一次，`n_verify` 仍然 ≥1。
   规则抓的是“从不验证”，不是“比平时少验证”。

## 4. 推荐的设计

两层监控：

```
第一层：确定性规则
  - 从不 run_tests
  - 出现新的红测试
  - 连续重复 >= 3 次
  → 高精度，低误报，用来抓已知违规

第二层：统计模型（Fisher）
  - 规则抓不到的过程偏离
  - 长空窗、异常动作组合、未知模式
  → 召回更高，但误报更高，用来做提醒/记录
```

第一层可以直接触发干预；第二层更适合低成本提醒，或者只记录。
