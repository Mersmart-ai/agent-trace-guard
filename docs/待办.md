## 一、已知问题（等真的碍事了再修）

### 1. `bad_output` 占用步数

**现象**：模型输出格式崩了，`policy` 返回 `{"tool": "bad_output"}`，
`agent_loop` 把它当成正常一步记进 history，**吃掉 30 步预算**。

**证据**：`_calibration/contradictory` 那条，**30 步里 18 步是 `bad_output`**。

**mini-swe-agent 的做法**：抛 `FormatError`，`while True` 继续，
**不占步**；但记 `n_consecutive_format_errors`，连续超阈值才退出（`RepeatedFormatError`）。

**改法**（等需要时再说）：

```python
MAX_CONSECUTIVE_BAD = 5
consecutive_bad = 0
step = 0
while step < MAX_TURNS:
    action = policy(step + 1, history)
    if action["tool"] == "bad_output":
        consecutive_bad += 1
        history.append(make_step(...))     # 仍然记，格式崩几次本身是数据
        if consecutive_bad >= MAX_CONSECUTIVE_BAD:
            reason = "RepeatedFormatError"
            break
        continue                            # ← 不占步
    consecutive_bad = 0
    step += 1
```

**为什么现在不改**：会影响已有 trace 的步数口径（之前 18 步是废的），
先按现状跑，等遇到"明明该够步数却撞上限"再改。

### 2. `_check_command` 挡不住藏在参数里的命令

**实测绕过**：

```bash
find . -exec sh -c 'ls' ;              # ✅ 放行（第一个词是 find）
tar -xf a.tar --to-command=sh          # ✅ 放行（第一个词是 tar）
```

**原因**：只检查"每段第一个词"和"有没有 `..` / 绝对路径"，
看不到 `-exec`、`--to-command` 这种"参数里能执行程序"的设计。

**为什么暂时不修**：要穷举每种命令的危险参数，写不完。
**兜底方案**：trace 里记着每条命令，事后能扫出来。这也正是项目要做的事。
