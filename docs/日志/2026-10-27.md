### 10-28 · 评审与动手

**评审四份设计文档。** 结论：选题（agent 评测 + 失败归因）在应届项目里属于上游，但有三个风险：

1. **"归因是空白"不成立。** 学术上 Who&When、TRAIL、MAST 等已在做 failure attribution；商业上 Galileo 做步骤级评估、LangSmith 做失败模式归纳。差异化应缩窄为"受控 harness + 强制写后测试"的步骤级归因，不要说"空白"。
2. **外部效度。** 40 个自造题 + 自己写的 agent 会被问"自说自话"；建议一半题源来自公开 benchmark，第二载体（Aider/SWE-agent）从"可选"升为"必做"。
3. **周期。** 18 周 / 540h 对求职窗口太长；建议 6 周 MVP：10 题、真模型、30 条人工标注、Cohen's kappa。

**pytest 入门。** 在 `_play_test_pytest/` 跑通最小红→绿；浮点比较用 `pytest.approx`；除零用 `pytest.raises`。

**定任务结构。** `src/` 是 agent 工作区，`tests/` 是裁判且不能进工作区，另有 `task.md` 和 `meta.json`。

**建 `task_0001`。** `add` 写成 `a - b`，测试初始红。

**解决测试 import。** 测试写 `from calc import ...`；由运行方设 `PYTHONPATH` 指向工作区。试过在 `tests/conftest.py` 里改 `sys.path`，后来删掉——两套路径机制会打架，统一由 runner 设环境变量。

**第一批工具。** `run_tests`、`prepare_workspace`、`read_file`、`write_file`。`read_file`/`write_file` 用 `resolve()` + `is_relative_to()` 防止 `..` 越界。

**原则。** 提示词是请求，代码才是约束；路径安全、不能改测试，都必须由代码保证。

### 10-29 · agent 循环与模型接入

- 完成 `agent_loop`：policy 返回 action，loop 执行并把结果写入 `history`；`finish` 退出；`range(10)` 是最大步数。
- `run_tests` 返回值从退出码改成字典（`exit_code` / `stdout` / `stderr`），让模型能看到测试输出，而不是只知道"1"。
- 明确 `history` 的作用：模型没有记忆，每次调用都要把任务 + 完整历史重新发过去。
- 装 `openai` + `python-dotenv`，建 `.env`；DeepSeek 用 OpenAI 兼容接口（`base_url=https://api.deepseek.com`）。
- 用户自己写 `my_llm.py`；踩了变量名大小写的坑：`api_key` vs `DEEPSEEK_API_KEY`。
- 开始写 `model_policy`：system prompt + `task.md` + history → `call_model` → `json.loads` → action。
- 观察：有明确工具格式/规则的 prompt，成功率明显提高；但 `finish` 即使从 prompt 删掉仍可能出现——**prompt 删工具不等于代码禁用工具**。
- 结论：成功应由 `run_tests` 判定，不能由模型自述。`finish` 要么校验"最近一次测试通过"，要么由 harness 在测试通过时停。
