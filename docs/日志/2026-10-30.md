## 问题与解决

### 1. `JSONDecodeError: Extra data`

**现象**：`json.loads(resp)` 报错，但把 resp 打出来看，前面明明是合法 JSON。

**原因**：模型把"思考内容"写在了 JSON 后面：

```
{"type": "tool_call", ...}
No output? We need actually call tool...
```

`json.loads` 要求整段都是 JSON，多一个字符就失败。

**解法**：改用 `json.JSONDecoder().raw_decode()`——从第一个 `{` 开始解析，解析完就停，后面不管。配合 `resp.find("{")` 先定位起点。

### 2. 模型返回带「信封」

**现象**：返回的不是 `{"tool": ...}`，而是：

```json
{"type":"json_object","content":{"tool":"write_file","args":{...}}}
```

**原因**：模型训练时见过 OpenAI 原生格式 `{"type":"function","function":{...}}`，把 `type` 当成了工具调用的第一个键。同时又把 `response_format` 里的 `json_object` 缝了进去。

**当时的处理**：先想加"解包分支"，后来放弃——**这是治标**。

### 3. `<｜｜DSML｜｜ invoke>` 一堆标记

**现象**：开了 `response_format={"type":"json_object"}` 之后，`content` 里出现大量 `<｜｜DSML｜｜...>` 标记。

**原因**：DSML 是 DeepSeek 内部的工具调用标记。JSON mode 要求输出必须是合法 JSON，而 DSML 不是，于是服务端没法解析成 `tool_calls`，**当普通文本原样吐了出来**。

**解法**：**根本解法是换成原生 `tools=` 参数**，让 API 自己去解析。改完之后 DSML 和信封问题一起消失。

### 4. 批量跑的路径 bug

**现象**：`task.name / Path("task.md")` 拼出来的路径 `FileNotFoundError`。

**原因**：`task.name` 是**字符串**（`"task_0004"`），`字符串 / Path` 会算出相对路径 `task_0004/task.md`——**丢了 `tasks/` 前缀**。

**解法**：`task / "task.md"`。`task` 本来就是 Path，不用取 `.name`。

> 教训：类型对不代表值对。加了 `Path()` 也救不回丢掉的前缀。

### 5. 换了 FC 之后，10 步全是 `list_files`

**现象**：4 个任务全部 `max_turns`，`task_0002`/`0003` 的 10 步里没有一次 `read_file`。

**当时未解决，留到第二天。**

## 决定

**① 放弃"解包信封"，改用原生 `tools=`。**

理由：信封、`type`、DSML 三个问题是同一个病——**我在用自定义格式，模型在用原生格式**。与其一直打补丁，不如把原生协议接上。

**② `write_file` 的返回值保持 `"写入成功"，不回显 content。**

理由：content 已经在 `args` 里了，回显是重复。更重要的——**模型每轮收到完整 history，回显会让 token 翻倍**。

**③ trace 的字段由 `make_step` 一处统一产生。**

之前每个分支自己拼 dict，形状不一致。改成所有 step 都走 `make_step`，以后加字段只改一处。
